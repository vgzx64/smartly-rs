# Теория: SSD, NAND, контроллер, SMART, SATA vs NVMe

Материал к практическому заданию (этап 1). Источники указаны в конце.

## 1. Что такое SSD

**SSD (Solid State Drive)** — накопитель без подвижных частей: данные хранятся в
флеш-памяти **NAND**, а управление осуществляет **контроллер** с прошивкой.
Вместо магнитных пластин и головок — массив ячеек памяти, таблица преобразования
адресов и алгоритмы выравнивания износа.

Состав SSD:

| Компонент | Роль |
|---|---|
| NAND-чипы | хранение данных (SLC/MLC/TLC/QLC) |
| Контроллер | протокол (NVMe/SATA), ECC, FTL, управление |
| DRAM/SRAM кэш | таблица FTL, буферы записи (есть не у всех — DRAM-less SSD) |
| Прошивка | wear-leveling, GC, TRIM, bad-block management |
| Питание/независимая память | копия FTL для безопасного отключения (FTL cache) |

## 2. NAND-память

- **Типы ячеек** (сколько бит на ячейку): SLC (1 бит, ~100k P/E), MLC (2, ~10k),
  TLC (3, ~3k), QLC (4, ~1k). Больше бит → дешевле объём, но меньше
  **циклов стирания (P/E cycles)** и ниже скорость/надёжность.
- **Принцип записи**: запись идёт страницами (4–16 КБ), стирание — блоками
  (несколько МБ). Нельзя перезаписать ячейку «поверх» — сначала стирание блока.
- **Retention**: данные держатся за счёт заряда в транзисторе; заряд
  деградирует со временем и с каждым P/E-циклом. Отсюда — «срок хранения
  выключенного SSD» и зависимость надёжности от износа.
- **Износ и выравнивание**: контроллер распределяет записи по всем блокам
  (**wear-leveling**), чтобы ресурс расходился равномерно.
- **Over-provisioning (OP)**: часть NAND скрыта от пользователя (обычно 7–28%)
  — резерв для замены плохих блоков и ускорения GC. Важно для восстановления:
  «старые» данные могут остаться в OP-зоне.
- **Метрики**: **TBW** (сколько ТБ можно записать по гарантии), **DWPD**
  (сколько раз перезаписать диск в день в течение гарантии).

## 3. Контроллер и прошивка

- **FTL (Flash Translation Table)**: таблица соответствия LBA (адреса
  пользователя) → физический адрес в NAND. Именно её поведение объясняет,
  почему «удалённый файл» на SSD часто невосстановим: после TRIM контроллер
  помечает страницы свободными, а GC потом физически затирает их.
- **ECC / LDPC**: коды коррекции ошибок; по мере износа LDPC работает на
  пределе — отсюда поле **media_errors** в SMART (неисправимые ошибки чтения).
- **Bad-block management**: вывод из строя блоков из резерва (spare blocks),
  отсюда метрика **available_spare** и её порог.
- **Garbage Collection (GC)**: сбор свободных страниц, слияние блоков.
- **TRIM**: команда ОС «этих данных больше нет» → контроллер заранее
  готовит страницы к стиранию и не тратит ресурс на копирование мусора.
- **Безопасное выключение**: кэш FTL сбрасывается; **unsafe shutdowns** в SMART
  — счётчик аварийных отключений (риск рассинхронизации FTL).

## 4. SMART

**SMART** (Self-Monitoring, Analysis and Reporting Technology) — система
внутренней диагностики накопителя: контроллер ведёт счётчики и пороги,
программы (`smartctl`, `nvme`) их читают.

### Ключевые атрибуты SATA (ATA SMART)

| ID | Имя | Смысл |
|---|---|---|
| 5 | Reallocated_Sector_Ct | сектора, выведенные в резерв |
| 9 | Power_On_Hours | часы работы |
| 194/199 | Temperature | температура |
| 197 | Pending_Sector | нестабильные сектора (ждут проверки) |
| 198 | Offline_Uncorrectable | неисправимые при чтении |
| 173/233/231 | Wear/Life Left | износ / остаток ресурса SSD |
| 241/242 | Host Writes | суммарная запись от хоста |
| 233–242 (производ.) | SSR/program/erase fail | ошибки операций NAND |

Нормализованное значение (value) — «чем выше, тем лучше», raw — «сырое» число.
Атрибут со значением ниже **thresh** считается тревожным.

### NVMe SMART/Health Log (страница 02h)

Поля вместо номеров атрибутов:

- `critical_warning` — битовая маска: 0) запас ниже порога, 1) перегрев,
  2) деградация надёжности, 3) контроллер в read-only, 4) отказ
  энергонезависимой памяти;
- `percentage_used` — износ ресурса в % (может превышать 100);
- `available_spare` / `available_spare_threshold` — резерв блоков и порог;
- `media_errors` / `num_err_log_entries` — неисправимые ошибки;
- `data_units_read/written` — объём записи/чтения (1 data unit = 512 000 байт);
- `power_on_hours`, `power_cycles`, `unsafe_shutdowns`, `temperature`.

Отличие от SATA: поля стандартизированы для всех NVMe-дисков, SATA-атрибуты
частично зависят от производителя.

### Оценка состояния в smartly-rs

`smartctl -j -a` (SATA и NVMe) или `nvme smart-log` → единая структура `Health`
→ 10 нормализованных признаков → ML-модель + экспертные правила.


## 5. SATA vs NVMe

| | SATA (AHCI) | NVMe (PCIe) |
|---|---|---|
| Шина | SATA III (6 Гбит/с, ~550 МБ/с) | PCIe (x4 Gen3 ≈ 3.5 ГБ/с, Gen4 ≈ 7 ГБ/с) |
| Протокол | AHCI: создан для HDD | NVMe: создан специально для флеша |
| Очередь команд | 1 очередь, до 32 запросов | до 64 000 очередей × 64 000 команд |
| Задержка | выше (AHCI-обходы) | ниже (прямой путь через PCIe) |
| Форм-факторы | 2.5″, mSATA, M.2 (B+M ключ) | M.2 (M ключ), U.2, PCIe-карты |
| Управление питанием | ограничено | многоуровневые состояния |
| Sanitize/Secure Erase | ATA Secure Erase / Sanitize (ACS-3+) | Format NVM + Sanitize (crypto/block/overwrite erase) |

Практическое следствие: NVMe-диски иначе ведут себя при отказах (команды
`nvme format`, `nvme sanitize` вместо `hdparm --security-erase`), поэтому
smartly-rs выбирает методы диагностики и стирания по транспорту устройства.

## 6. Удаление данных на SSD без возможности восстановления

- **TRIM + discard** — «логическое» удаление: данные недоступны через ФС,
  но физические страницы (и OP-зона) могут остаться. Для защиты от
  форензики обычно недостаточно, для быстрой «очистки» — достаточно.
- **ATA Secure Erase / ATA Sanitize (SATA)**: контроллер затирает все
  страницы, включая резервные зоны. Надёжно.
- **NVMe Format NVM (--ses=1 user-data / --ses=2 crypto) и Sanitize
  (-a 1 block erase, -a 2 crypto erase, -a 3 overwrite)**: штатные команды
  NVMe; crypto-erase уничтожает ключи шифрования — данные нечитаемы сразу.
- **Шифрование (SED/LUKS)**: самый быстрый способ — уничтожить ключ
  (`cryptsetup luksKillSlot`, стирание ключа SED). Восстановление невозможно,
  даже если страницы физически остались.
- **Почему `shred` на SSD плох**: wear-leveling перемешивает физические
  адреса, запись «поверх» не гарантированно перезаписывает старые страницы.

## 7. Восстановление данных с SSD

1. Читать как можно меньше: каждое чтение иссякающего блока — стресс.
2. Снимать **образ** (`ddrescue`) с других машин, напрямую, без USB-мостов.
3. Повреждённый диск: несколько проходов ddrescue, при физическом отказе —
   лаборатория (PC-3000, DeepSpar).
4. Удалённые файлы: на SSD с TRIM обычно **невосстановимы** — это
   нормальное поведение, а не поломка.
5. Всегда — резервное копирование заранее (3-2-1: три копии, два носителя,
   одна вне места).
